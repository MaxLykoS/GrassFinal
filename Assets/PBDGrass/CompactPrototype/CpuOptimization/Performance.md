# CPU 局部选择与增量交接：优化结果

2026-10-21。当前 Contact Lab 保留 **32768 根活动 XPBD、144×144 米驻留窗口、663552 根驻留容量、中景完整到 52 米／52～64 米过渡、256 米外围窗口及 12 个碰撞体**。近景仍为 60 Hz、8 个子步、每子步 3 次迭代。

最终默认视角中，CPU 完整 tick 从 **19.80 ms 降至 2.31 ms**，降低 **88.3%**。移动换页尖峰也显著降低。场景、求解器、光照、压缩格式和烘焙资产均未改变，GPU Buffer 仍为 **224852832 B（214.44 MiB，含外围）**。

## 同机重跑的原版与最终版

RTX 3080 Ti、Ryzen 7 5800X，Unity 2022.3.62f2c1、D3D11；1600×900 HDR、4× MSAA，默认相机 `(0,16,-14)`。单位 ms。原版来自本轮开始前保存的 `Reference.zip`，使用同一测试脚本重新执行。

| CPU 区间 | 原版平均 | 最终版平均 | 最终版 P95 |
| --- | ---: | ---: | ---: |
| 模拟池选择 | 7.744 | 0.693 | 1.094 |
| LOD 交接管理 | 11.840 | 1.395 | 2.025 |
| 完整 tick 的 CPU 准备与提交（含以上两项） | 19.801 | 2.310 | 3.365 |
| 草场更新及相机提交总区间 | 20.340 | 2.793 | 4.189 |

每组预热 120 tick，静止组各 300 样本；每样本恰好推进一个完整 tick，活动量始终为 32768。数据没有通过降低模拟频率、关闭接触或混入空闲帧改善。CPU 总区间包含准备、Unity API 提交及可能的等待，不能与 GPU 时间直接相加。

最终版 96 米对照的 CPU tick 为 1.919 ms，144 米为 2.310 ms；早一轮同配置两者分别为 1.929 / 2.006 ms。CPU 成本存在系统负载波动，但已不再随驻留面积扩大 2.25 倍而近似翻倍。候选排序、边界预热仍需要 CPU；本轮没有声称管理成本为零。

## 相机移动与换页

两版均运行 24 秒、1440 tick 的 36 米往返，保留运动碰撞体和风。各发生 8 次换页，每次更换 1152 格。

| CPU 指标 | 原版 | 最终版 |
| --- | ---: | ---: |
| 所有移动采样的总区间平均 | 15.242 | 2.222 |
| 所有移动采样的总区间 P95 | 20.277 | 2.694 |
| 换页调用中位数 | 15.316 | 3.657 |
| 换页帧总区间中位数 | 48.981 | 5.796 |
| 换页帧总区间最大值 | 61.367 | 9.176 |

没有删掉第一次换页。最终版八次换页帧分别为 9.18, 5.76, 5.62, 5.19, 5.29, 5.83, 6.10, 6.92 ms。换页仍有开销，这些是当前 144 米窗口、8 米分页步长的测量，不是任意速度或传送的最坏情况保证。

初步局部化后，换页仍有 25～45 ms 尖峰。排查发现 `UpdateDisplay` 读取 `data.Blades.Length` 会触发 `RefreshCpuWorld`，按模板重新生成新页的 CPU 节点、杆段和元数据镜像；GPU 实际早已完成新页生成。这是额外 CPU 计算，并非 GPU 同步回读。改为现有的 `data.BladeCount` 后，显示 dispatch 的数量相同，诊断消费者显式读取数据时仍会刷新镜像。

## 实时运行与 GPU

- Editor Play 实时复测：20 秒内 1200 tick，约 60.01 Hz，无丢弃模拟时间；1192 帧推进 1 tick、4 帧推进 2 tick，没有持续 4 tick 补帧。实际 tick 的 CPU 准备与提交平均 2.274 ms。
- 最终版 Windows Mono Development Player：约 60.01 Hz，无丢弃模拟时间，CPU 准备与提交平均 **1.112 ms/实际 tick**；其中选择 0.336 ms、交接 0.650 ms。
- 实时测试以墙钟推进累加器，预热 10 秒、采样 20 秒，使用离屏 Camera.Render；没有把包含大量零 tick 帧的离屏 FPS 当作用户窗口帧率。先前约 13 FPS 的持续补帧现象未复现。
- 最终默认视角 GPU 时间戳：XPBD 求解＋近景重建 3.251 ms，中景显示更新 0.715 ms，相机渲染 0.931 ms。**32768 根 XPBD 的 1 ms GPU 目标仍未达到。**

本轮没有修改 GPU 算法；CPU 提交节奏、系统负载和频率等会影响测到的 GPU 区间，不把 GPU 数值波动计为求解器优化收益。GPU 中景更新、绘制和存储仍随范围增长。其他已打开的 Unity 工程保留，未改变设备频率设置。

## 改动与正确性

- 流式格按环形地址直接查询，非流式格建立静态空间桶；只筛选近景和碰撞区域，并预先计算排序分数。
- 交接只处理前后两次活动集合、未完成过渡和局部预热带。只上传脏分类/映射区间，保持碰撞优先级、滞回、确定性同分规则、历史释放与分配顺序。
- 600 组随机池用例通过；最终版与原版独立初始化，逐步比较 2400 tick，包含 12 次换页、预热模式切换、接触与释放、快速返回、整窗替换和 Reset。全程 32768 活动草。
- 14 个检查点逐位比较近景节点/速度、方向/角速度、塑性、位置、法线、完整中景压缩姿态、GPU 分类/历史映射和风状态，均一致。同步回读仅在正确性测试内使用，性能测试不读取这些状态。
- Contact Lab 完整 2701 tick 表现测试通过：12 个碰撞体、9 次换页、倒伏进入中景并返回、四种观察视角、三层颜色、有限近景状态；最大近景节点距离 1.5845 米，倒伏标记在往返前后均约 1.0879。
- 原联合 baseline 的 1440 tick 回归通过：32768 XPBD＋98304 贝塞尔，交接播种和塑性保留误差为零，Scene 相机行为保持；八种材料的临时重烘焙与接受资产的节点、控制点、方向、频率和阻尼差异均为零。

Editor 实时及 Contact Lab 表现测试在局部分类/增量上传实现完成时执行；之后的计数访问修复重新通过完整独立对照，联合 baseline、Player 和 `_final` 性能组使用最终代码。最终源码、场景及未改动资产的哈希在 `Sources.json` / `UnchangedAssets.json` 中。
