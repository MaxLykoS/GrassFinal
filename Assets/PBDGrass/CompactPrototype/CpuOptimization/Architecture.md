# CPU 局部选择与增量交接

范围：`GrassSimulationPool`、`GrassTieredHandoff` 的 CPU 管理，以及共享查询的接线。物理方程、GPU kernel、压缩格式、烘焙资产、场景参数均不变。

## 模拟池

`GrassGridQuery` 对流式格直接按世界整数坐标寻址环形槽；非流式格使用构造时的静态空间桶。查询只提供保守候选，精确距离、碰撞优先级、满池滞回、同分按 grid ID 排序、LRU 淘汰仍沿用原规则。碰撞区域逐个做局部查询，避免每个驻留格遍历全部碰撞体。

清理上一轮选中/优先格的标记，而非清空整张驻留表。排序分数在候选阶段计算一次，避免比较器重复计算距离。当前近景预算内的候选仍排序；本轮没有改变选择算法或延迟更新频率。

## LOD 交接

每轮工作集合由上一轮活动格、当前活动格、未完成过渡、近景边界预热带和碰撞预热区组成。相机突然移动时，旧活动格和未结束过渡继续进入集合，因此不能只看新相机附近。自适应前向预热仍采用原来的速度、持续时间和 20 米上限。

世界状态/历史槽映射仍保留原布局；只有发生变化的条目才上传。邻近脏区合并，碎片太多时用一个包含区间限制驱动调用次数。新页只上传受影响的分类、映射、剔除格和朝向区间。显示 dispatch 改读 `BladeCount`，避免 `Blades.Length` 隐式重建只供诊断使用的 CPU 世界镜像；GPU 的新页生成保持原样。初次创建和 Reset 仍允许整表初始化。

候选先按 grid ID 排序，再使用原来的预热优先级比较器；历史释放保持 slot 顺序、分配保持 grid 顺序，保留同分情况下的确定性。这关系到实际进入时使用哪份历史，不能只比较近景数量。

## 保留的成本与限制

- GPU 中景风响应/姿态更新仍遍历驻留数据，绘制和数据容量仍随中景范围增长。
- 流式换页的世界重绑定、节点/姿态初始化仍然存在；CPU 局部分类不等于异步资源加载。
- 初始化仍建立 CPU 生成数据。此次没有优化启动耗时或压缩 CPU 镜像。
- 原有边界历史预算耗尽时仍报错；没有以丢弃过渡或降低碰撞质量掩盖容量不足。
- 静态空间桶适用于非流式格位置不变的路径；流式位置变化使用环形地址。

## 验证与复现

`Reference.zip` 保留本轮修改前的四份管理实现，`Reference.json` 记录 SHA-256。`prepare_cpu.py parity` 将这些实现重命名为独立类型，放入 D 盘隔离工程，与当前实现独立初始化、接收相同输入。不会把旧版模拟状态覆盖到新版。

`CpuParity.cs.txt` 检查有重叠的随机静态格、负坐标、两种排名模式、碰撞增删、淘汰、满池，及实际场景的动态碰撞、释放、塑性、移动边界、预热开关、快速往返、完整世界替换和 Reset。每步比较选择顺序/槽与 CPU 分类映射；关键阶段逐位比较实际 GPU 近景节点、速度、方向、塑性、位置、法线和完整中景压缩姿态，并检查上传后的 GPU 分类/映射。同步回读只发生在这个正确性验证中。

性能沿用 `Showcase/Performance` 的原生 D3D11 timestamp、非阻塞查询与独立 CPU Stopwatch 插桩。`prepare_cpu.py reference` 可重放优化前实现；`optimized` 恢复当前版本。所有插桩及 DLL 只安装到 D 盘隔离工程。`run_checks.ps1` 提供 parity、optimized、reference、combined、player 和 final 阶段；final 包含最后一次修复后的对照和移动复测。性能测试与逐位回读验证分开运行。
