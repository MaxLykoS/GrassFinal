# Contact Lab 扩大中景后的性能记录

2026-10-21。结论：本次扩容的主要瓶颈是 **CPU 模拟池选择与近中景交接管理**。96→144 米驻留窗口使它们每 tick 合计从约 9.24 ms 增至 18.68 ms。扩大版在独立编辑器 Play 测试中进入每帧 4 tick 的持续补帧状态，录得 **13.04 FPS、75.79 ms CPU/帧**。

本轮没有优化或修改正式运行代码、场景、物理质量、烘焙数据。插桩、原生计时插件和 Player 构建均只放在 D 盘独立验证工程。

## 测试负载与方法

- RTX 3080 Ti、Ryzen 7 5800X，Unity 2022.3.62f2c1、D3D11。
- 当前 `PBDGrassContactLab.unity`，32768 活动 XPBD、8 子步、每子步 3 次迭代、12 个动态/静态碰撞体、随机风、塑性及既有光照。
- 原范围对照：96×96 米驻留窗口、294912 根容量、中景 28～36 米过渡；扩大版：144×144 米、663552 根容量、中景 52～64 米过渡。两者外围均为 256 米。
- 默认高位相机 `(0,16,-14)`；另测俯视 `(0,100,0)`，两个容量的俯视都采用相同的 72 米正交半高。相机 XZ 同时决定近景模拟中心，因此两个视角的物理接触分布也不同。
- 1600×900 HDR、4× MSAA，显式离屏 `Camera.Render`，关闭 VSync 与帧率限制。覆盖实际计算与场景绘制，排除可见编辑器界面和窗口呈现；这些离屏 FPS 不等于用户窗口中的显示 FPS。
- 固定负载：每采样帧执行恰好一个完整 1/60 秒 tick。每组预热 120 tick；静止每组 300 样本，两个移动组各 1440 样本，合计 **4980 个有效 GPU 时间戳样本**，所有样本活动量均为 32768，失效/丢弃均为 0。
- GPU 采用原生 D3D11 timestamp/disjoint，后续帧以 `DONOTFLUSH` 非阻塞轮询。没有同步读取节点、方向、塑性或可见实例缓冲。CPU 采用 Stopwatch，单独记录池选择、交接、流式、模拟提交、剔除及相机提交。
- 实时对照分别运行 Editor Play 和 Windows Mono Development Player；预热 10 秒，采样 20 秒，将真实墙钟增量传给原有 60 Hz 累加器，保留最多 4 tick 的补帧设置。截图在计时结束后生成。

## 默认高位视角：单个完整 tick

扩大版合并两轮，共 600 样本；原范围为 300 样本。单位 ms，P95 表示 95% 样本不超过该值。

| CPU 项目 | 原范围平均 | 扩大版平均 | 扩大版 P95 |
| --- | ---: | ---: | ---: |
| 模拟池选择 `Pool.Select` | 3.558 | 7.307 | 7.689 |
| 近中景交接管理 `Handoff.Select` | 5.682 | 11.374 | 11.768 |
| 完整 `Advance` 准备与提交，包含上两项 | 9.402 | 18.854 | 20.024 |
| 本次草场更新及相机提交总区间 | 9.783 | 19.275 | 20.460 |

| GPU 项目 | 原范围平均 | 扩大版平均 | 扩大版 P95 |
| --- | ---: | ---: | ---: |
| XPBD 求解＋最后子步的近景几何重建 | 3.036 | 3.974 | 4.946 |
| 烘焙风状态推进 | 0.008 | 0.011 | 0.013 |
| 中景形态更新、压缩写入及交接显示 | 0.425 | 0.877 | 1.305 |
| 中心草剔除 | 0.008 | 0.011 | 0.011 |
| 外围筛选和实例生成 | 0.041 | 0.047 | 0.051 |
| 相机渲染区间，包含场景与目标解析 | 0.791 | 1.139 | 1.564 |
| 其中不透明阶段，是上一项的子集 | 0.728 | 1.037 | 1.445 |

CPU 与 GPU 可重叠，不能把两表直接相加。GPU 端 selection / stream / whole-frame 时间戳区间可能包含等待 CPU 提交的空闲时间，因此没有把它们当成纯内核耗时列入主表。扩大版的两轮近景 GPU 均值分别为 4.237 / 3.712 ms，保留波动及长样本；未停止用户的其他 Unity 进程，不能将全部 GPU 差值归因于中景面积。本轮仍不满足近景求解＋重建 1 ms 目标。

## 编辑器中的帧率骤降

| 实时观测 | 原范围 Editor Play | 扩大版 Editor Play |
| --- | ---: | ---: |
| 每个实际执行 tick 的 CPU `Advance` | 9.558 ms | 18.820 ms |
| 实际物理更新速率 | 60.00 tick/s | 52.16 tick/s |
| 是否持续触发 4 tick 补帧 | 否 | 是，260/260 采样帧 |
| 每帧 CPU 工作 | 见原始逐帧记录 | 75.794 ms |
| 帧间隔 P95 | 9.736 ms | 81.091 ms |
| 20 秒采样中的丢弃模拟时间 | 0 | 2.607 s |

扩大版测得 13.04 FPS。单 tick 的 CPU 管理超过 16.67 ms 后，下一帧累积更多待模拟时间；每帧重复池选择和交接，最终持续触发上限 4 tick。对应源码是 `PBDGrassPatchRenderer.Advance` 的 accumulator / MaxCatchUpSteps 逻辑，以及 `Tick` 内每次调用的 `SelectPool`。

原范围的无限速离屏循环含大量无物理 tick 的轻量帧，其平均循环帧率很高；不把这个数字作为实际游戏 FPS 或 XPBD 预算。评估求解预算始终使用上面的完整 tick 表。

Player 与 Editor 不同：独立 Player 的原范围/扩大版 CPU `Advance` 分别约 **6.084 / 12.113 ms/实际 tick**，二者均维持约 60 tick/s，没有持续补帧。扩大版 Player 的每帧 tick 均值仅 0.088，所以其离屏平均帧率也不能替代完整模拟耗时。当前低帧率在编辑器中得到复现，不能直接外推为发行版本同样只有 13 FPS。

## 其余对照与换页尖峰

| 配置 | CPU 总区间平均 | GPU 相机渲染平均 |
| --- | ---: | ---: |
| 原范围，同一俯视构图 | 9.947 ms | 1.858 ms |
| 扩大版，同一俯视构图 | 19.419 ms | 3.466 ms |
| 扩大版，关闭分层色 | 20.392 ms | 1.222 ms |
| 扩大版，关闭全部碰撞体 | 11.480 ms | 0.878 ms |

关闭分层色没有改善 CPU 瓶颈。关闭碰撞体后，池选择/交接分别降至 3.547 / 7.213 ms；这项对照同时关闭物体显示，仅用于定位，正式场景仍保留 12 个碰撞体。

两轮 24 秒往返，各发生 8 次实际换页，每次替换 1152 格。首次测试的第一次换页出现 **7124.704 ms** CPU 停顿，数据完整保留。随后同路线复测没有再出现秒级停顿，符合首次使用的初始化/编译开销特征，但未单独证明具体原因。

复测 8 个换页帧：流式处理 CPU 中位数 **15.249 ms**、最大 **39.741 ms**；包含随后正常 tick 与渲染提交的总 CPU 中位数 **49.345 ms**、最大 **79.988 ms**。换页内立即重分类一次，随后 tick 又选择一次，因此换页帧会重复这部分管理成本。不能用整段移动的平均值稀释这些尖峰，也不能把包含 CPU 等待的 GPU stream 时间戳区间当成纯 GPU 换页内核耗时。

## 代码对应与下一步

1. `GrassSimulationPool.Select` 每 tick 扫描全部驻留格，并逐格检查交互区域；`GrassTieredHandoff.Select` 也扫描全部格并处理交互边界。窗口扩大使格数从 9216 增至 20736，这些工作仍发生在主线程。
2. `GrassTieredHandoff.UpdateDisplay` 按全部驻留叶片数 dispatch，扩大后覆盖 663552 个槽；不只更新画面里可见的蓝色草。其 GPU 成本也增长，但当前 CPU 两项合计约 18.68 ms 是更大的问题。
3. 优先调整 CPU 候选范围、交互区域检索和交接增量更新，并消除同一换页帧重复重分类；需要保留碰撞优先级、历史和 LOD 连续性。随后再单独处理中景 GPU 更新范围和俯视绘制成本。本轮未执行这些优化，也没有通过减少近景数量、子步或碰撞体数量修改正式场景。
